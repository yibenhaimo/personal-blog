ブラウザーに URL を入力してページが表示されるまでには、IP、DNS、ルーター、TCP、HTTP、HTTPS など、多くの仕組みが数秒の間に働いています。

## ネットワークとは

ネットワークは、複数の機器が共通のルールで情報を交換するための接続です。

- **LAN** は家庭、学校、会社などの小さなネットワークです。
- **Internet** は世界中の多くのネットワークをつないだものです。

Wi-Fi に接続するとまず LAN に入ります。遠くの Web サイトを見るには、その LAN がインターネットにも接続されている必要があります。

## Web ページを開く流れ

`https://example.com` を開くと、概ね次のように進みます。

```text
browser → DNS で名前を調べる → サーバー IP を得る
→ ルーターや回線を通る → Web サーバー → 応答を表示
```

## IP、ドメイン、DNS

IP アドレスはネットワーク上の住所です。IPv4 の例は次のようになります。

```text
192.168.1.10
```

人にとって数字の住所は覚えにくいため、`example.com` のようなドメイン名を使います。DNS はドメイン名を IP アドレスに変換する、インターネットの電話帳のような仕組みです。

Windows では次のコマンドで DNS の結果を確認できます。

```powershell
nslookup example.com
```

## パケット、ルーター、ポート

ネットワーク上の大きなデータは、小さな単位であるパケットに分けて送られます。ルーターは宛先を見て、パケットを次の場所へ転送します。

IP アドレスが建物の住所なら、ポートはその中の部屋番号です。

| サービス | よく使うポート |
| --- | --- |
| HTTP | 80 |
| HTTPS | 443 |
| SSH | 22 |
| ローカル開発 | 3000、5173、8080 など |

## TCP、UDP、HTTP、HTTPS

| プロトコル | 主な特徴 | 利用例 |
| --- | --- | --- |
| TCP | 順序と確実な到着を重視 | Web、ログイン、ダウンロード |
| UDP | 低遅延を重視 | 通話、配信、ゲーム |

HTTP はブラウザーと Web サーバーがやり取りするための形式です。`200`、`404`、`500` などの status code も HTTP の一部です。

HTTPS は HTTP に TLS の暗号化を加えたものです。サーバーの確認と、通信中の内容を保護するのに役立ちます。

## Wi-Fi に接続してもネットが使えない理由

Wi-Fi 接続は、端末とルーターがつながったことを示すだけです。ルーターの回線が切れている、DNS が失敗している、ログイン用ページが必要、サイト側が停止している、といった原因は別にありえます。

確認には次のコマンドが便利です。

```powershell
ipconfig
nslookup example.com
ping example.com
```

`ping` が失敗しても、必ずしもサイトが壊れているわけではありません。応答を拒否するサーバーも多いためです。

ネットワークの中心にある考え方は簡単です。**正しい宛先に、共通のルールで、機器同士が情報を送ること。** これを覚えると、DNS、443、TCP、HTTPS という言葉も少しずつつながって見えてきます。
