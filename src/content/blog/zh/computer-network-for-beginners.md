每天我们都在刷视频、发消息、打开网页，但很少会想：为什么在地址栏输入一个网址，几秒后页面就出现了？为什么 Wi-Fi 明明连上了，网页却打不开？为什么有的网站前面是 `http`，有的是 `https`？

这些问题都属于计算机网络。

本文不讲复杂公式，也不要求你会编程。我们只跟着一次“打开网页”的过程，认识最常见的网络概念：**IP 地址、域名、DNS、数据包、路由器、端口、TCP、UDP、HTTP 和 HTTPS。**

## 1. 计算机网络是什么？

计算机网络可以简单理解成：

> 让多台设备能够交换信息的一套连接方式和规则。

你的手机、笔记本、学校服务器和网站服务器，本来都是独立的设备。只有通过网线、Wi-Fi、光纤、基站等连接起来，并且遵守同一套通信规则，才能互相传送数据。

网络并不等于互联网。

- **局域网（LAN）**：范围小的网络，例如宿舍、教室、家里的 Wi-Fi。
- **互联网（Internet）**：把大量局域网和运营商网络连接在一起的全球网络。

当你的电脑连接家里的 Wi-Fi 时，它先进入一个局域网；当它访问远处的网站时，数据会经过互联网到达网站服务器。

## 2. 打开网页时，到底发生了什么？

假设你在浏览器输入：

```text
https://example.com
```

大致会发生下面这些事：

```text
浏览器
  ↓ 询问域名对应的地址
DNS
  ↓ 返回服务器 IP
浏览器
  ↓ 通过网络发送请求
路由器 / 运营商 / 互联网
  ↓
网站服务器
  ↓ 返回网页数据
浏览器显示页面
```

后面的章节，就是把这条流程拆开讲清楚。

## 3. IP 地址：网络中的“门牌号”

现实世界寄快递需要地址，网络世界发送数据也需要地址。这个地址就是 **IP 地址**。

常见的 IPv4 地址长这样：

```text
192.168.1.10
```

每个数字范围大致是 0 到 255，四段数字用点隔开。

你可以把 IP 地址理解成一栋楼的门牌号。数据想送到某台设备，就必须知道它的 IP。

不过，IP 地址分为两类：

| 类型 | 例子 | 用途 |
| --- | --- | --- |
| 私有 IP | `192.168.x.x`、`10.x.x.x` | 家庭、学校、公司内部网络使用 |
| 公网 IP | 由运营商分配 | 可以在互联网中被定位和访问 |

家里电脑通常拿到的是私有 IP；家里的路由器再通过一个公网 IP 与外面的互联网通信。

## 4. 域名：给 IP 起一个好记的名字

虽然 IP 地址很适合电脑识别，但不适合人记忆。相比记住：

```text
93.184.216.34
```

我们更愿意记：

```text
example.com
```

这种人类容易记住的名字，叫做**域名**。

域名和 IP 的关系很像：

```text
联系人姓名  ↔  手机号码
域名        ↔  IP 地址
```

你在浏览器输入域名，浏览器仍然需要先找到真正的 IP 地址，才能把请求送出去。

## 5. DNS：互联网的“电话簿”

把域名翻译成 IP 地址的系统，叫做 **DNS（Domain Name System，域名系统）**。

例如浏览器想访问：

```text
example.com
```

它会询问 DNS：“这个域名对应哪个 IP 地址？”DNS 返回答案后，浏览器才能继续连接服务器。

所以，当你遇到“网络看起来正常，但某个网站的域名打不开”时，问题有时不在网站本身，而在 DNS 解析。

在 Windows 的终端中，可以使用下面的命令查看域名解析结果：

```powershell
nslookup example.com
```

它不会修改任何设置，只是查询信息。

## 6. 数据包：大文件不会一次性飞过去

网络传输的数据通常不会整块发送，而是会拆成很多小块，叫做**数据包（packet）**。

这就像寄一套很多册的书：

```text
一本大书 → 拆成多个包裹 → 分别运输 → 到终点后重新整理
```

每个数据包除了正文，还会带上“从哪里来、到哪里去、属于第几块”等信息。这样即使它们走的路线不同，接收方也能尽量把内容按正确顺序拼回来。

拆包的好处是：

- 一条线路可以同时给很多人传数据；
- 某个包丢失时，只需要补发这一小部分；
- 网络设备更容易转发和管理数据。

## 7. 路由器：帮数据选择下一站

数据从你的电脑到网站服务器，通常不会直线到达，中间会经过很多网络设备。

路由器的工作可以理解成“分拣中心”：它查看数据包的目标地址，再决定下一站应该往哪里走。

```text
你的电脑 → 家用路由器 → 宽带运营商 → 多个网络节点 → 网站服务器
```

这就是“路由”。不同的数据包不一定走完全相同的路线，只要最后能到达目的地即可。

在 Windows 中，可以使用：

```powershell
tracert example.com
```

查看数据大致经过了哪些网络节点。它不一定能显示完整路线，因为有些设备会拒绝回应这类探测请求。

## 8. 端口：同一台电脑上的“房间号”

IP 地址只能找到一台设备，但一台设备上可能同时运行很多服务：网页、邮件、数据库、游戏服务器……这时需要用**端口（port）**区分具体服务。

可以把它理解成：

```text
IP 地址 = 一栋楼
端口 = 楼里的房间号
```

一些常见端口：

| 服务 | 常见端口 |
| --- | --- |
| HTTP 网页 | 80 |
| HTTPS 网页 | 443 |
| SSH 远程登录 | 22 |
| 本地开发服务器 | 常见为 3000、5173、8080 等 |

当你访问：

```text
https://example.com
```

浏览器通常会默认连接 HTTPS 的 443 端口，所以地址栏里不必专门写出来。

## 9. TCP 和 UDP：两种传输方式

数据包要怎么可靠地传送？常见有两种传输协议：TCP 和 UDP。

| 协议 | 特点 | 常见场景 |
| --- | --- | --- |
| TCP | 更重视完整、顺序和可靠性 | 网页、登录、文件下载 |
| UDP | 更重视速度和低延迟 | 语音通话、直播、在线游戏等 |

### TCP：像挂号信

TCP 在正式传数据前会先建立连接，并尽量保证：

- 数据是否完整；
- 顺序是否正确；
- 丢失的数据能否重传。

它像寄挂号信：慢一点，但更强调“必须送到”。网页内容、账号密码和文件下载通常不能随便缺字，所以经常使用 TCP。

### UDP：像实时对讲

UDP 更轻量，通常不会为每个数据包反复确认是否到达。少量数据丢失时，它宁愿继续发送，也不希望画面或声音卡住。

这很适合实时场景：视频通话中偶尔丢失一小段声音，比整段声音停住等待重传更容易接受。

## 10. HTTP：浏览器和网站说话的规则

浏览器向服务器要网页时，需要双方都理解同一种“说话格式”。这套格式就是 **HTTP（HyperText Transfer Protocol）**。

一个非常简化的请求，大概像这样：

```text
GET / HTTP/1.1
Host: example.com
```

服务器收到后，会返回状态和内容：

```text
HTTP/1.1 200 OK
Content-Type: text/html
```

你常见的状态码也来自 HTTP：

| 状态码 | 常见含义 |
| --- | --- |
| 200 | 请求成功 |
| 301 / 302 | 页面跳转 |
| 403 | 没有访问权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部出错 |

## 11. HTTPS：给网页通信加上保护层

HTTP 本身不加密。如果在不安全的网络中直接传输敏感信息，理论上可能被中间人窥探或篡改。

HTTPS 可以理解为：

```text
HTTP + TLS 加密保护
```

当网址以 `https://` 开头时，浏览器会先验证服务器身份，并协商加密方式，再传输网页数据。

这并不代表网络中所有信息都完全不可见，但它能显著保护网页内容、登录信息和传输过程不被随意读取或篡改。输入密码、支付信息、提交表单时，应优先确认网站使用了 HTTPS。

## 12. Wi-Fi 连上了，为什么还是不能上网？

“连上 Wi-Fi”只说明你的设备和无线路由器之间连通了，不代表路由器一定能连到互联网。

常见情况包括：

1. 路由器到运营商的宽带连接断了；
2. DNS 解析出了问题；
3. 学校、酒店或机场 Wi-Fi 需要先在网页中登录；
4. 某个网站自己的服务器出故障；
5. 当前网络对某些地址或端口有限制。

排查时，可以按这个顺序思考：

```text
设备能否连上 Wi-Fi？
↓
其他网站能否打开？
↓
域名能否解析？
↓
目标服务器是否正常？
```

## 13. 给新生的网络排查三件套

下面三个命令都只是检测，不会修改你的电脑设置：

```powershell
ipconfig
nslookup example.com
ping example.com
```

它们分别可以帮助你：

| 命令 | 用来查看什么 |
| --- | --- |
| `ipconfig` | 当前网络适配器、IP、网关等信息 |
| `nslookup` | 域名能否解析成 IP |
| `ping` | 是否能收到目标主机的回应 |

不过要注意：`ping` 不通不一定代表网站坏了，因为很多服务器会主动拒绝响应 ping。

## 最后记住这张图

当你打开一个网页时，可以把过程记成：

```text
输入域名
  ↓
DNS 把域名查成 IP
  ↓
浏览器通过 TCP / 网络设备连接服务器端口
  ↓
HTTP(S) 请求网页内容
  ↓
服务器返回数据包
  ↓
浏览器把网页显示出来
```

计算机网络听上去很大，但核心始终是同一件事：**让不同设备在正确的地址、用共同的规则，可靠地交换信息。**

理解了这条主线，以后再听到 IP、DNS、端口、443、TCP、HTTPS 这些词，就不会只觉得它们是一堆缩写了。
