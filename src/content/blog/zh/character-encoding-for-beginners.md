不用怕，本文不需要任何计算机基础。看完以后，你至少能回答三个问题：

1. 为什么中文有时会乱码？
2. UTF-8、GBK 是什么？
3. 写代码、写 Markdown、做网页时到底应该选哪个？

## 1. 电脑其实不认识“你”“好”

电脑最底层只能处理两种状态：有电和没电。我们通常把它写成：

```text
0 和 1
```

例如，一个数字可以写成一串二进制：

```text
01001010
```

但人写文章时需要的是汉字、字母、标点、表情。电脑要保存这些文字，就必须先约定一件事：

> 某一串数字，究竟代表哪个字符？

例如可以约定：

```text
65 代表 A
66 代表 B
```

有了共同约定，电脑保存数字，人就能看到文字。

## 2. 两个容易混淆的词：字符集和编码

日常交流里，大家常把它们混着说，但可以这样简单理解：

| 名词 | 可以把它理解成 |
| --- | --- |
| 字符集（character set） | “有哪些字、每个字的编号是多少”的字典 |
| 编码（encoding） | “怎样把编号存成 0 和 1”的写法 |

举个不严谨但好懂的例子：

- 字符集像一本《汉字字典》，告诉你“你”这个字有一个编号。
- 编码像邮寄方式，告诉你怎样把这个编号装进信封，传给另一台电脑。

所以，常说的“UTF-8 字符集”在严格意义上更像是一种**编码方式**。不过日常把它叫“字符集”，一般也不会造成误解。

## 3. 最早只有英文：ASCII

早期计算机主要在英语环境中使用，于是有了 **ASCII**。

ASCII 可以表示：

- 英文字母：`A` 到 `Z`、`a` 到 `z`
- 数字：`0` 到 `9`
- 常见标点：`,`、`.`、`!`
- 一些控制符：换行、制表符等

它只需要 128 个位置，就能放下这些常用字符。

问题也很明显：ASCII 没有中文、日文、韩文、阿拉伯文，更没有 emoji。只靠 ASCII，根本写不了“你好”。

## 4. 中文电脑曾经常用 GBK

为了让电脑能表示中文，国内出现过一系列中文编码标准，例如 GB2312、GBK 和 GB18030。

你最常听到的是 **GBK**。它可以表示大量简体中文字符，也兼容英文 ASCII 字符，因此很长一段时间里，Windows 中文环境中的旧软件和旧文本经常使用 GBK。

GBK 的优点是：

- 对简体中文支持好；
- 在一些旧版中文 Windows 软件中兼容性较高。

它的局限是：

- 它主要为中文环境设计；
- 面对很多其他语言和 emoji 时不够方便；
- 和国际项目、网页、跨平台工具混用时，更容易发生编码不一致的问题。

因此，你现在还能在旧项目、政府或学校的历史系统、某些 CSV 文件中见到 GBK，但新项目通常不再优先选择它。

## 5. Unicode：给全世界文字发统一编号

不同国家如果都各自发明一套编码，交流会很痛苦。于是出现了 **Unicode**。

Unicode 的目标很简单：

> 给全世界常见的文字、符号和表情分配统一编号。

例如，Unicode 不只关心中文，也关心：

- 英文、法文、德文等拉丁文字；
- 中文、日文、韩文；
- 阿拉伯文、俄文、泰文；
- 数学符号、货币符号；
- emoji，例如 😀。

Unicode 中的编号常写成 `U+` 开头，例如：

```text
U+0041  是 A
U+4F60  是 你
U+597D  是 好
```

注意：Unicode 更像一本“全球字符编号表”。它解决了“这个字符编号是什么”的问题，但还需要一种方式把编号真正存进文件。

## 6. UTF-8：今天最常用的编码方式

UTF-8 就是把 Unicode 编号保存成字节的一种方式。

它之所以几乎成了互联网默认标准，原因很简单：

1. **能表示 Unicode 中的大量字符**，包括中英文、其他语言和 emoji。
2. **兼容 ASCII**：纯英文文本在 UTF-8 中和 ASCII 的写法一致。
3. **适合网络传输**：网页、接口、代码仓库和多数现代工具都默认支持它。

UTF-8 会根据字符的不同，使用不同数量的字节：

| 内容 | UTF-8 通常占用 |
| --- | --- |
| 英文、数字和常见英文标点 | 1 个字节 |
| 常见中文 | 3 个字节 |
| 很多 emoji | 4 个字节 |

这就是为什么“你好”看起来只有两个字，但文件大小会比两个英文字符大一些。

## 7. UTF-8 和 GBK 的关系：像两套不同的密码本

假设你用 UTF-8 把“你好”保存进文件，但某个程序误以为它是 GBK：

```text
保存时：UTF-8
打开时：GBK
```

程序会拿错“密码本”去翻译字节，于是就出现乱码。

反过来也一样：

```text
保存时：GBK
打开时：UTF-8
```

同一段字节会被解释成错误的字符，甚至直接显示成方块或问号。

所以乱码的核心并不是“中文坏了”，而是：

> 写入时的编码，和读取时的编码不一致。

## 8. 为什么有时是乱码，有时只是问号？

两种情况不一样：

- **乱码**：程序把字节按错误规则翻译了，还能勉强翻译出一些奇怪字符。
- **问号或方块**：程序根本找不到对应字符，或者当前字体没有这个字形。

例如一个很新的 emoji，在旧系统上显示成方块，不一定是编码问题，也可能只是系统字体不支持它。

## 9. UTF-8、UTF-16、UTF-32 又是什么？

它们都是 Unicode 的编码方式，区别主要在于“一个字符怎么存、占多少空间”。

| 编码 | 简单理解 | 常见场景 |
| --- | --- | --- |
| UTF-8 | 长度可变，英文省空间，兼容性最好 | 网页、代码、Markdown、接口、GitHub |
| UTF-16 | 通常以 2 个字节为单位 | Windows 内部和部分软件 |
| UTF-32 | 每个字符固定占 4 个字节 | 少见，简单但更占空间 |

作为新生，不需要背细节。只要记住：**创建文本文件、写代码、写网页时，优先选 UTF-8。**

## 10. 写代码和做网页时，应该怎么选？

下面是最实用的建议：

| 场景 | 建议编码 |
| --- | --- |
| `.js`、`.py`、`.java`、`.c` 等代码文件 | UTF-8 |
| Markdown 文档 | UTF-8 |
| HTML 网页 | UTF-8 |
| JSON、YAML、CSV 数据文件 | 优先 UTF-8 |
| 新建数据库和接口 | UTF-8 / UTF-8 对应的 Unicode 配置 |
| 老旧中文系统导出的文本 | 先确认是否为 GBK |

网页中还常会看到这一行：

```html
<meta charset="UTF-8">
```

它是在告诉浏览器：“请按 UTF-8 读取这个网页。”

## 11. 发现乱码时，按这个顺序排查

### 情况一：用编辑器打开文本文件时乱码

在 VS Code 右下角可以看到当前文件编码。点击它，然后尝试：

1. **使用编码重新打开**；
2. 依次尝试 `UTF-8`、`GBK`；
3. 找到显示正常的编码后，再选择“使用 UTF-8 保存”。

注意：如果文件已经被错误编码保存并覆盖过，原文可能无法完全恢复。所以遇到乱码时，先另存或备份，不要立刻反复保存。

### 情况二：网页显示乱码

检查三处是否一致：

1. HTML 文件保存时是不是 UTF-8；
2. 有没有 `<meta charset="UTF-8">`；
3. 服务器响应头有没有告诉浏览器正确的编码。

### 情况三：Excel 或 CSV 打开中文乱码

很多 CSV 文件本身是 UTF-8，但 Excel 直接双击打开时可能会按本地默认编码猜测。

更稳妥的方法是：打开 Excel 后，使用“数据 → 自文本/CSV”，在导入时手动选择 UTF-8。

## 12. 给新生的最终口诀

如果你只想记住一句话，请记住：

> **新文件默认用 UTF-8；旧中文文件怀疑 GBK；乱码先查“保存和打开的编码是否一致”。**

字符集和编码看起来像很底层的知识，但它每天都在影响我们：发消息、写 Word、保存代码、上传 CSV、浏览网页，背后都离不开它。

下次再看到乱码时，不用慌。先问自己：**这个文件是按什么编码保存的？我又是按什么编码打开的？**
